# 🤖 ai — AI チャット

画像、複数ターンの会話、ツール、個人の長期記憶、共有サーバー コンテキストをサポートする、選択可能なモデルを使用して AI とチャットします。 AI は、実際の使用量に基づいて ** グローバル通貨 (ボットの世界通貨)** を差し引きます。これは無料の機能ではありません。

## 会話コマンド

|コマンド |説明 |
| --- | --- |
| `/ai メッセージ [画像] [新規会話] [モデル]` | AI とチャットします。画像を添付したり、新しい会話を開始したり、モデルを指定したりできます。
| `/ai会話削除` |確認後、現在のサーバー/DM スコープの会話履歴をクリアします。
| `/ai履歴` |現在のスコープの最新の 10 件の会話エントリを非公開で表示します。
| `/ai既定モデル モデル` |独自のクロスサーバーデフォルトテキストモデルを設定する |
| `/ai表示設定 コンテナ コスト モデル` |コンテナー、請求情報、モデル情報を表示するかどうかを設定します |
| `y!ai [model] [message]` | AIチャットのプレフィックスバージョン。モデル名を先頭に置くことができます |
| `y!ai-new [message]` |現在のスコープの履歴をクリアし、新しい会話を開始します。
| `y!ai-clear` |現在のスコープの会話履歴をクリアします |
| `y!ai-history` |現在のスコープの会話履歴を表示する |

> `y!` はデフォルトのプレフィックスです。サーバーのプレフィックスが変更されている場合は、代わりにそのサーバーの現在のプレフィックスを使用します。

AI の返信は、カードや画像ギャラリーの形にしたり、リンクボタンを付けたりすることがあります。いくつかの選択肢から選ぶ必要があるときは、AI がフォローアップのボタンやメニューを付けることもあります。押すとその文字があなたの次のメッセージとして AI に送られ、通常のメッセージと同じく課金されます。初期状態では誰でも押せますが、AI が質問した本人だけに限定することもできます。

## グローバル知識ベースと投稿

知識ベースはすべてのユーザー・サーバー・DM で共用し、個人／サーバーメモリとは別に保存します。AI は毎回、関連する承認済み知識を自動取得し、必要に応じて自発的に検索・全文取得します。

| コマンド | 説明 |
| --- | --- |
| `/ai-knowledge search [query]` | 承認済み知識を検索。キーワードなしでは最近の知識を表示 |
| `/ai-knowledge submit title content [source_url] [knowledge_id] [expected_version]` | 公開知識を投稿。改訂には知識 ID・現在のバージョン・完全な置換原稿が必要 |
| `/ai-knowledge status submission_id` | 自分の投稿結果を非公開で確認。Bot オーナーはすべて確認可能 |
| `y!ai-knowledge [query]` | プレフィックス版の知識検索 |
| `y!ai-knowledge submit "タイトル" 内容` | プレフィックス版の投稿 |
| `y!ai-knowledge status submission_id` | プレフィックス版の投稿状況確認 |
| `y!ai-knowledge review submission_id` | Bot オーナー：審査ボタンを表示。投稿原文は非公開で確認 |
| `y!ai-knowledge approve submission_id [理由]` | Bot オーナー：AI に却下された投稿を含めて手動で承認 |
| `y!ai-knowledge reject submission_id [理由]` | Bot オーナー：未公開の投稿を手動で却下 |
| `y!ai-config knowledge-channel #チャンネル` | 通知先を設定。`off` で無効化 |
| `y!ai-knowledge remove knowledge_id` | Bot オーナー：知識を検索・自動取得から取り下げ |

- 審査には既存の `ai_review_model` を使用し、`y!ai-config review-model` で設定します。自動審査または Bot オーナーの手動承認後に公開します。
- 審査通知には「投稿を確認／手動で承認／手動で却下」ボタンが付き、Bot オーナーのみ操作できます。再起動後も利用でき、審査待ち・審査中・不承認・審査失敗の投稿を手動審査できます。審査者 ID を記録して再通知し、遅れて届いた AI の結果は手動決定を上書きしません。古い通知は投稿 ID を指定した `review` または `approve` で審査できます。
- 手動承認でも改訂バージョンを確認し、新しい内容の上書きや取り下げ済み知識の復活はできません。繰り返し承認しても重複公開せず、公開済みの知識は `remove` で取り下げます。
- タイトルは最大 80 文字、本文は最大 4,000 文字、ユーザーごとに毎時 5 件まで。同一投稿は重複登録せず、改訂のバージョン確認で新しい内容の上書きを防ぎます。
- 審査失敗時は最大 3 回試行し、再起動後に未完了の審査を再開します。通知失敗時は保持して再送し、通知先を後から設定した場合も未配信分を送信します。
- 管理者には投稿 ID・結果・モデル・説明を通知し、不承認／未審査の本文を転載しません。未公開投稿の確認は投稿者と Bot オーナーに限定します。
- AI は「覚えて」と言われるのを待たず、明確で長期的に有用な低リスク情報を自発的に検索・整理・保存し、公開可能な一般的解法を投稿します。個人情報やサーバー限定情報は元の範囲を維持します。削除には明示的な依頼が必要です。
- 審査に追加の固定ボット通貨料金はありません。通常の AI 会話の料金は従来どおりです。モデルの承認は正確性の保証ではなく、時点に依存する情報は再確認が必要です。

## メモリとクロスサーバーコンテキスト

AI は 3 つの異なるタイプのコンテキストを使用します。 1 つをクリアしても他のものはクリアされません。

|タイプ |範囲と動作 |
| --- | --- |
|会話履歴 |サーバーごとに個別に保管されます。 DM はグローバル/DM スコープを使用します。 `/ai会話削除` および `y!ai-clear` は、そのスコープの会話履歴のみをクリアします。 |
| `user_global` 個人的な思い出 |現在のユーザーに関連付けられ、サーバー間で共有されます。 AI は関連する記憶を自動的に取得し、ユーザーが安定した低リスクの好みや個人的な事実を明確に述べたときに、それらを積極的に更新することもできます。 |
| `guild_shared` サーバー メモリ |現在のサーバー内でのみ共有され、サーバーの雰囲気、共有設定、共通リスト、または共有ジョーク/リファレンスに使用されます。サーバーの管理/管理者権限を持つユーザーによって明示的に要求された場合にのみ変更できます。 |

- 各長期記憶エントリは 2,000 文字に制限されており、メモリ スペースごとに最大 80 エントリが存在します。長すぎるコンテンツは、黙って切り詰めるのではなく、複数のエントリに分割するように求められます。
- システムは、モデルのコンテキストを設定するときに、現在のメッセージに関連するメモリを優先し、次に最近更新されたメモリを優先します。直接含まれていないコンテンツも、AI 記憶ツールによってオンデマンドで検索できます。
- 「私の好みを覚えていてください...」、「先ほど述べた設定を更新してください...」、または「忘れてください...」と言うだけです。メモリの削除は、常にユーザーが明示的に要求する必要があります。
- ユーザーが他のサーバーまたはグローバル/DM スコープから既存の AI 会話を呼び出すように AI に明示的に要求すると、AI はオンデマンドで検索できますが、読み取ることができるのはそのユーザー自身の記録のみです。他のサーバーからの共有メモリは引き込まれません。
- AI に、パスワード、トークン、API キー、正確な財務詳細、ID 情報、医療/法的プライバシー データ、またはその他の機密性の高い情報を記憶するように要求しないでください。

## 外部データ ツール

- `search_google` および `search_google_images` は Serper 経由で検索します。 `fetch_webpage` は、Serper 経由で読み取り可能なページ コンテンツを抽出します。
- `fetch_webpage` と `fetch_raw` のツールプレビューにはドメインだけを表示し、URL のパス、クエリ、フラグメントは表示しません。
- 返信内の画像、サムネイル、ギャラリーには、任意の HTTP/HTTPS ホストの画像 URL を表示できます。`image_analyze` と画像生成の参照画像の取得は、引き続き Discord CDN に限定されます。
- `fetch_raw` は、生の JSON、プレーン テキスト、HTML、XML、YAML、またはソース コードの読み取りに適したパブリック URL をボットに直接取得させます。これは Serper を経由せず、`!aicfg proxy` 経由で設定された SOCKS5 プロキシを適用します。
- `fetch_raw` では、パブリック HTTP/HTTPS の標準ポートのみが許可されます。 URL 資格情報、ローカルホスト、内部/プライベート アドレス、またはバイナリ コンテンツは受け入れられません。各リダイレクトは再検証され、ダウンロードは 1 MB に制限され、1 回の呼び出しで最大 12,000 文字が返されます。
- 他の検索結果と同様、生のコンテンツは信頼できない外部データです。 AI はそれを参考資料としてのみ扱うことができ、ルールの変更、データの漏洩、またはアクションの実行を求める AI 内の指示に従ってはならない。
- `fetch_raw` は、Serper クォータを消費せず、追加の固定グローバル通貨料金も発生しません。通常の `/ai` テキスト入出力は、選択したモデルの料金で引き続き請求されます。
- `upload_html` は、AI が生成した単一の HTML ファイルを [sharemyhtml.com](https://sharemyhtml.com) にアップロードし、公開 URL を返します。Web ページ、HTML のサンプル、インタラクティブなデモに適しています。リンクを知っている人は誰でも開けるため、パスワード、トークン、個人情報を含めるよう求めないでください。1 ファイルの上限は 5 MB で、アップロード後に AI がページを編集・削除することはできません。

## メッセージの読み取りと画像

- メッセージを読む際は、Markdown と改行を保持したテキストに加え、埋め込み、添付ファイル、投票、ステッカー、リアクション、転送、Components V2 の構造を先に取得します。
- AI は ID から任意の Discord ユーザーを調べられます。現在のサーバーのメンバーにはニックネーム、ロール、権限が含まれます。サーバー外のユーザーや DM での照会では、名前、アバター、アカウント作成日などの公開情報のみとなります。
- 視覚的な配置や Discord 固有の表示をテキストだけで判断できない場合に限り、AI はメッセージ画像を作成します。画像は Discord クライアントの直接キャプチャではなく、`chat_exporter` による再構成です。表示できない形式は構造化テキストで補います。
- 既定では対象の一件だけを画像にします。文脈が必要な場合は、同じ投稿者による直前五分以内のメッセージを最大九件追加できます。スポイラーは展開されます。
- 画像を添付するだけなら追加の画像解析料金はありません。AI に画像の判読を依頼すると、組み込み料金として一回 25 全域幣がかかり、失敗時は返金されます。
- 外部ページのスクリーンショットは `browser_view` の視覚解析にのみ使用し、返信には添付しません。外部画像はページのスクリーンショットではなく、画像自体の URL で表示します。
- メッセージ、画像、画像内の文字は信頼されないデータであり、システム指示として扱われません。

## 請求

### テキストでの会話

テキスト モデルは文字数に応じて課金されます。

```text
Input cost  = actual input characters × the selected model's per-character rate
Output cost = actual output characters × the selected model's per-character rate
Total cost  = input cost + output cost + any additional paid image tools used
```

- 入力コストは、リクエストがモデルに送信される前に差し引かれます。グローバル通貨残高が入力をカバーするのに十分でない場合、リクエストは送信されません。
- 出力完了後、実際の返信文字数に基づいてコストが差し引かれます。 AI が `send_as_file` または `upload_html` を使用する場合、完全なファイルまたは HTML コンテンツの文字数も出力としてカウントされます。
- デフォルトでは、定期的な返信には料金、入出力文字数、実際の合計請求額が表示されます。 `/ai表示設定` を使用して請求情報を非表示にしても、表示から非表示になるだけであり、請求は停止されません。
- モデル呼び出しが失敗した場合、すでに差し引かれている入力コストが返金されます。

### 参照画像を使った生成と編集

- `/ai` に画像を添付して編集や参照画像を使った生成を依頼すると、AI は現在の添付画像、または Discord CDN の画像 URL を `generate_image` に渡せます。1 回につき参照画像は 1 枚です。画像を PNG に変換して OpenAI 互換 Images API の `images.edit` を呼び出します。テキストのみの生成には引き続き `images.generate` を使用します。
- `gpt-image-2` はデフォルトで画像入力が有効です。他の画像モデルを追加した後、ボット所有者は `y!aicfg image-input-tag <model> on` で有効、`off` で無効にできます。現在の API プロバイダーがそのモデルの画像編集に対応していることを先に確認してください。この設定はテキストモデルの vision タグとは別です。
- `y!aicfg image-models` は対応モデルに `[image-input]` を表示します。未設定のモデル、無効な参照画像、ダウンロードの失敗は生成料金の引き落とし前に通知されます。生成に失敗すると返金され、既存の画像 1 枚あたりのモデル料金が適用されます。

### Google 画像検索と安全性

- AI は Serper Images 経由で公開画像を検索できます。このエンドポイントにはセーフサーチ オプションがないため、ボットは最大 3 つの候補を順番にダウンロードし、現在構成されている AI レビュー モデルに渡します。レビューがタイムアウトした場合、形式が無効である場合、または結果が決定的でない場合、画像は表示されません。
- 検索ごとにボット所有者の Serper API クォータが消費され、候補のレビューによってレビュー モデルのプロバイダーの使用量も生成されます。現在、どちらも固定グローバルコストとしてユーザーに個別に請求されることはありませんが、通常の `/ai` テキスト入出力は選択したモデルの料金で引き続き請求されます。
- 検索ツールでレビューに合格した画像は、元のメタデータを削除し、PNG/JPEG に再エンコードして Discord の添付ファイルとしてアップロードします。この取得処理には、サイズ、ピクセル寸法、形式、リダイレクト、内部・プライベートアドレスの制限が適用されます。
- 画像のレビューには間違いが含まれる可能性があり、Google 画像の検索結果は著作権のクリアランスを意味するものではありません。 AI にはソース ページが含まれている必要があります。画像は現在の返信にのみ使用され、長期間キャッシュされません。
- ボット所有者は、`y!aicfg proxy socks5://host:1080` を使用してイメージ ダウンロード用の専用 SOCKS5 プロキシを設定し、`y!aicfg proxy` を使用してマスクされたステータスを表示し、`y!aicfg proxy clear` を使用してマスク状態をクリアできます。 `sock5://` は、`socks5://` に自動的に修正されます。
- プロキシは、ボット自体がダウンロードするイメージと `fetch_raw` にのみ適用されます。 Discord、OpenAI 互換 API、または Serper API に使用される接続は変更されません。 URL に資格情報が含まれている場合、ステータスと応答にはマスクされた値のみが表示されます。

## メンション&返信モード

この機能はデフォルトでは無効になっています。 「サーバーの管理」または「管理者」権限を持つユーザーは、次のコマンドを使用して設定できます。

|コマンド |説明 |
| --- | --- |
| `/ai管理 メンションモード 有効` |このサーバーのメンション/返信トリガーを有効または無効にする |

- 直接メンションの場合、ボットのメンションはメッセージ内の空白以外の最初のコンテンツである必要があります。文の途中または最後に配置してもトリガーされません。
- 返信トリガーの場合、この機能が有効になった後に AI が正常に送信した一時メッセージに返信する必要があり、その Discord の返信ではボットのメンションが有効のままである必要があります。 「メンション」をオフにして返信してもトリガーされません。
- メッセージの先頭からボットのメンションを削除した後も、テキスト コンテンツが残っている必要があります。メッセージがメンションのみ、空白文字のみ、または添付ファイルのみの場合、ボットは応答しません。通常のボット テキスト コマンドも再度トリガーされません。
- AI 応答メッセージ ID はメモリ内にのみキャッシュされ、サーバーあたり最大 200 エントリが最大 24 時間保持されます。これらはボットが再起動されるか、この機能が無効になるとクリアされるため、再起動前の古い AI メッセージによってトリガーされることはありません。
- 他の機能が同じコンポーネント形式を使用する可能性があるため、システムはコンポーネント V2 を介して AI メッセージを識別しません。この AI モジュールによって実際に記録された応答メッセージ ID のみを受け入れます。
- メンションと返信は、`y!ai` と同じ完全な処理および請求フローに従い、追加の固定コストはかかりません。テキスト入出力は引き続きユーザーのデフォルトのモデル料金で請求され、サーバーが支払者を指定している場合は、代わりにその支払者に請求されます。

## サーバー支払者

デフォルトでは、AI リクエストを行う各ユーザーは自分の残高から支払います。 「サーバーの管理」または「管理者」権限を持つユーザーは、自分自身をこのサーバーの統一支払者として設定できます。一度設定すると、サーバー内の他の全員によるテキストおよび有料画像ツールの使用は、代わりに指定された支払者の世界通貨で請求されます。

|コマンド |説明 |
| --- | --- |
| `/ai管理 請求 設定` |自分自身をこのサーバーの AI 支払者として設定します |
| `/ai管理 請求 表示` |現在の支払い方法/支払者を表示 |
| `/ai管理 請求 クリア` |指定された支払者をクリアし、全員が個別に支払う状態に戻します。
| `y!ai-server-billing` |現在の支払い方法/支払者を表示 |
| `y!ai-server-billing set` |支払者を自分に設定する |
| `y!ai-server-billing clear` |指定された支払者をクリアします |

現在、別のメンバーを支払者として指定することはできません。 `set` は、コマンドを自分で実行する管理者のみを設定します。

## サーバーのカスタム AI プロンプト

管理者は、サーバー コンテキスト、応答スタイル、または設定を最大 1,800 文字で指定できます。これは `guild_shared` メモリとは異なります。カスタム プロンプトは固定コマンドですが、サーバー メモリは AI が検索して更新できる長期データです。

|コマンド |説明 |
| --- | --- |
| `/ai管理 プロンプト 設定 プロンプト` |サーバーのカスタム AI プロンプトを設定する |
| `/ai管理 プロンプト 表示` |現在のプロンプトを表示する |
| `/ai管理 プロンプト クリア` |現在のプロンプトをクリア |
| `y!ai-server-prompt` |現在のプロンプトを表示する |
| `y!ai-server-prompt [content]` |プロンプトを設定する |
| `y!ai-server-prompt clear` |プロンプトをクリア |

## タスクスキルとファイル分析

AI はタスクに必要な手順とツールを必要なときだけ読み込みます。ブラウザー操作、出典付きのウェブ調査、Discord 会話の調査、添付ファイルの読み取り、データ分析、Meta Threads へのテキスト投稿に対応します。「昨日の会話をメッセージリンク付きでまとめて」「この CSV を分析して整理済みファイルを添付して」のように依頼できます。

- `/ai` の「ファイル」オプション、テキストコマンドの添付、または閲覧可能なメッセージの添付を指定できます。テキスト、CSV/TSV、JSON、PDF、DOCX、XLSX に対応し、上限は 8 MB です。PDF はテキスト抽出のみで OCR はありません。表計算の数式は実行しません。
- 大きな結果は分割して読める一時リソースになります。JavaScript の変数とリソースは同じリクエスト内でのみ保持され、完了、キャンセル、タイムアウト後に破棄されます。CSV/JSON などのテキスト結果は添付できます。
- ブラウザー操作は既存の Discord の許可／拒否フローを使います。Node は同じ権限確認済みハンドラーを呼び出し、ホストのファイル、ボットの認証情報、ネットワークへ直接アクセスしません。
- ブラウザー操作は原則として Node REPL を使い、Python Playwright を介したロール／CSS ロケーター、キーボード入力、ビューポート座標のマウス操作に対応します。Docker が起動できない場合は従来のツールを利用できます。ref がタイムアウトしたら画面を再確認し、同じ ref を繰り返さず安定したロケーターに切り替えます。
- 進捗表示は Node REPL と表示され、kernel が実際に動いた場合だけ返信のモデルフッターにも `Node REPL` が付きます。ツール結果と秘匿済み診断ログには Node バージョン、kernel ID、実行番号、ブリッジ呼び出し数を記録します。コードやブラウザーの内容はこれらのログに出しません。
- Meta Threads は設定済みプロファイルのログイン状態を使い、テキストとリンクに対応します。メディアのアップロードには対応しません。明示的な投稿依頼がある場合にのみ公開し、結果を確認してリンクを返します。下書きや動作テストでは投稿しません。アカウント操作はボット所有者と所有者が許可した投稿者に限定されます。

### 所有者向けの実行設定

更新済み Python requirements と Linux Docker daemon をボットのホストに用意し、`docker pull node:24-alpine` でイメージを事前取得してください。ボットは自動取得やホスト上での直接実行へ切り替えません。サンドボックスが利用できなくても、既存のブラウザーツールと Piston は利用できます。

- `!aicfg node-repl`：現在の設定を表示します。
- `!aicfg node-repl on [image]`：事前取得した Node 互換イメージで有効化します。`off` で無効化します。
- `!aicfg browser-cdp <profile CDP URL>`：既存の方法でブラウザーを設定します。
- `!aicfg threads-publisher <Discord ユーザー ID> on`：Threads アカウントの操作を許可します。`off` で追加の許可を取り消します。ボット所有者は初期状態で許可されています。

各 kernel はネットワーク無効、読み取り専用ファイルシステム、worker 一つだけの読み取り専用マウント、非特権ユーザー、CPU・メモリー・プロセス数の制限を使います。同時実行はボットごとに二つまでです。リクエストには 10 分の期限、最大十二ラウンド、JavaScript 経由を含む合計 48 回のツール呼び出し上限があり、終了時にコンテナーを削除します。
