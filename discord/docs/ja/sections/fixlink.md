# 🔗 FixLink — リンクフィクサー管理自動化

FixLink は、サーバー内の組み込みおよび管理者が構成したカスタム プラットフォーム リンクを検出し、Discord に適切に埋め込まれる固定リンクを生成します。この機能はデフォルトでは無効になっています。

|コマンド |説明 |
| --- | --- |
| `/fixlink 設定` |インタラクティブな設定パネルを開く |

## 配信モード

- **標準返信**: ボットは、元のリンク、作成者のページ、および利用可能なフィクサーを返信します。元のリンクが `||...||` スポイラー タグでラップされている場合、修正された応答でもスポイラーが保持されます。固定メッセージに 7 秒後にプレビューがない場合は自動的に削除され、プレビューが成功すると元のメッセージの埋め込みが折りたたまれます。
- **Webhook の置換**: 投稿者の名前とアバターを使用して固定メッセージを再送信します。 7 秒経過してもプレビューが表示されない場合、Webhook メッセージは元のテキストに戻ります。元のメッセージは、これが完了した後にのみ削除されます。
- Webhook モードは「すべてのリンク」または「トラッキング パラメーターのみ」に設定できます。後者は、サポートされている少なくとも 1 つのリンクに追加のクエリまたはフラグメント データが含まれている場合にのみリンクを置き換えますが、クリーンなリンクは引き続き標準応答を使用します。
- プラットフォームのコンテンツ識別に必要なクエリ パラメータは、追跡パラメータとしてカウントされません。 YouTube の `v` および `t`、Instagram の `img_index`、および Bilibili の `p`。
- Webhook メッセージには、元のメッセージの作成者のみが使用できる永続的な削除ボタンが付属しています。
- Webhook が返信関係、ステッカー、投票、または音声メッセージを保持できない場合、元のテキストが保持され、代わりに標準の返信が使用されます。

## 組み込みプラットフォーム

- 22 の組み込みプラットフォームがサポートされています: Threads、Twitter/X、Instagram、TikTok、Reddit、Facebook、Bilibili、Pixiv、Pinterest、YouTube、Twitch、Bluesky、Spotify、Mastodon、Tumblr、DeviantArt、Imgur、Weibo、Newgrounds、PTT、Roblox、および Fur Affinity。
- Spotify、Mastodon、Tumblr、Imgur、YouTube はデフォルトで無効になっていますが、設定パネルから個別に有効にすることができます。
- 設定パネルでは、組み込みプラットフォームを選択し、個別に有効または無効にし、Webhook モードに使用するプライマリ フィクサーを指定できます。標準モードでは、そのプラットフォームで利用可能なすべてのフィクサーがリストされます。
- プログラムに組み込まれた正確なソース ドメイン、パス ルール、および HTTPS フィクサーのみが使用されます。非公式のジョーク ドメインや、Awesome Fixers リストの非推奨のサービスは含まれません。
- サービスの選択は [FixTweetBot Awesome Fixers](https://github.com/Kyrela/FixTweetBot#awesome-fixers) に基づいています。

## スレッド

- `threads.com`、`threads.net`、`/@user/post/id`、および `/share/code` リンクをサポートします。
- 標準モードでは、FzThreads と FixEmbed の両方が表示されます。 Webhook モードでは、プライマリ サービスを選択できます。
- `/share/code` は制限付きで公式スレッド投稿 URL に解決され、公式投稿パスを使用して FzThreads および FixEmbed リンクを生成するために使用されます。解決が失敗した場合にのみ、FzThreads 共有 URL にフォールバックします。
- `/share/code` は追跡タイプのリンクとして扱われるため、「追跡パラメーターのみ」Webhook モードでも処理されます。
- 追跡の削除を有効にすると、スレッド URL のクエリとフラグメントが削除されます。

他の組み込みプラットフォームの場合、追跡の削除を有効にすると、コンテンツの識別に必要なクエリ パラメーターのみが保持されます。 YouTube の `v`、Instagram の `img_index`、または Bilibili の `p`。

## カスタム プラットフォーム

- サーバーごとに最大 10 個、正確なソース ドメインとパス プレフィックスによって一致します。
- 構造化クエリ フィクサーのみが許可されます: HTTPS エンドポイント、ソース URL パラメーター名、および静的クエリ。
- ワイルドカード、正規表現、IP エンドポイント、`{url}` テンプレート、またはドメイン置換は受け入れられません。
- 追跡削除が有効な場合、どのソース クエリ キーを保持する必要があるかを構成できます。何も設定されていない場合は、すべてのクエリ パラメータが保持されます。
- 「パラメーターのみの追跡」Webhook モードは、`keep_query_keys` が構成されているカスタム プラットフォームの追加のクエリ パラメーターのみを評価します。キーが設定されていない場合、どのパラメータがパラメータを追跡しているかを推測できません。

## スキップされたメッセージ

FixLink は実際のユーザーによって送信されたメッセージのみを処理します。 `<https://example.com/...>` でラップされたボット、Webhook、およびリンクからのメッセージは処理されません。
