# 🛡️ モデレート — モデレーションツール管理者

ユーザー管理ツールの完全なセットを提供するコア モデレーション モジュール。期間文字列の解析 (例: `1h`、`30m`、`7d`) をサポートし、複数のユーザーを同時に処理できます。すべてのモデレーション アクションは、通知システムに自動的に統合されます。

|コマンド |説明 |
| --- | --- |
| `/moderate` |キック、禁止、ミュート、ブラックリストなどのアクションを含むモデレーション メニューを開きます。
| `y!moderate` `y!m` |モデレーション コマンドのプレフィックス バージョン |
| `y!moderate_reply` `y!mr` |返信されたメッセージの作成者を管理する |
| `/アクション作成` |モデレーション アクションのカスタムの組み合わせを構築する |
| `/モデレーション通知` |モデレーションアナウンスを手動で送信する |
| `/モデレーション通知先` |モデレーションアナウンスチャンネルを設定します。ケース ID を他のボットから継続できるように、メッセージ履歴の読み取り権限も付与することをお勧めします。
| `/モデレーション通知形式` |お知らせテンプレートとケース ID 形式を編集、プレビュー、またはリセットする |
| `/カスタムアクション追加` |カスタム サーバー モデレーション アクションを追加または更新する |
| `/カスタムアクション削除` |カスタムサーバーモデレーションアクションを削除する |
| `/カスタムアクション一覧` |カスタム サーバー モデレーション アクションを表示する |

> **期間形式:** `s` / `秒`、`m` / `分鐘`、`h` / `小時`、 `d` / `天`、`w` / `週`、`M` / `月`、`y` / `年` と、`1d12h` のように組み合わせることができます。

## アクション文字列

`y!moderate` および `/一括モデレーション` の `action` パラメーターは、アクション文字列形式を使用します。複数のアクション (最大 5 つ) をカンマ `,` で区切って連鎖させることができます。 `/アクション作成` を使用して、対話型インターフェイスを通じて文字列を生成することもできます。

|アクション |フォーマット |説明 |
| --- | --- | --- |
| `ban` | `ban <duration> <delete-message-duration> <reason>` |ユーザーを禁止します。 `0` の期間は永続を意味します。 `0` のメッセージ削除期間は、メッセージが削除されないことを意味します。
| `kick` | `kick <reason>` |ユーザーをキック |
| `mute` | `mute <duration> <reason>` |ユーザーをミュートします。デフォルトでは 10 分間です。 `timeout` または `to` も使用できます。
| `unban` | `unban <reason>` |ユーザーの禁止を解除する |
| `unmute` | `unmute <reason>` |ミュートを外します。 `untimeout` も使用できます。
| `delete` | `delete <warning message>` |必要に応じて公開警告を付けてメッセージを削除します (`{user}` はユーザーを指します)。
| `warn` | `warn <warning message>` |チャンネルで公開警告を送信する |
| `send_mod_message` | `send_mod_message` |設定されたアナウンス チャンネルにモデレーション アナウンスを送信します。 `smm` も使用できます。
| `force_verify` | `force_verify <duration>` |ユーザーに Web 認証の完了を強制します (ServerWebVerify を有効にする必要があります)。

> **例:**
> `ban 7d 1d rule violation` — 7 日間の禁止、最終日のメッセージを削除
> `mute 30m watch your behavior, warn {user} please mind what you say` — 公開警告とともに 30 分間ミュートします
> `delete_dm your message has been deleted, mute 1h rule violation` — メッセージを削除 + DM 通知 + 1 時間ミュート
> `ban 0 0 serious violation, smm` — 永久禁止し、モデレーション通知を送信します

## カスタムモデレーションアクションパラメータ

カスタム アクションは、`{1}` ～ `{9}` を使用して、呼び出し時に渡される位置パラメータにアクセスできます。 `{1}` は必須パラメータです。 `{1:default value}` は、最初のパラメーターが指定されていない場合のフォールバックを提供します。パラメータには 1 から始まる連続した番号を付ける必要があり、カンマは常にアクションの区切り文字として機能します。

```text
/custom-action-add name:spam action:mute {1:10m} {2:洗版}, smm
spam 30m "重複洗版"
```

上記の例は `mute 30m 重複洗版, smm` に展開されます。引用符を使用すると、スペースを含むテキストが単一のパラメータとして扱われます。必要なパラメータが欠落している場合、追加のパラメータが指定されている場合、循環参照がある場合、または展開が 5 アクションを超えている場合、実行前に操作全体がキャンセルされます。

## モデレーション通知テンプレート

構成されていない場合は、現在のマークダウン アナウンス形式が使用されます。管理者は、`/モデレーション通知形式` またはサーバー Web パネルを介してテンプレートを編集できます。テンプレートは、プレーン テキスト、単一の埋め込み、または両方の組み合わせを生成できます。

共通の変数:

- `{user}`, `{user_name}`, `{user_id}`, `{user_avatar}`
- `{moderator}`, `{moderator_name}`, `{moderator_id}`, `{moderator_avatar}`
- `{reason}`, `{action}`, `{case_id}`
- `{guild}`, `{guild_id}`, `{guild_icon}`
- `{reported_message}`、`{report_context}`、`{ai_note}` (ReportSystem コンテキストでのみ設定されます)

AutoReply と同じ埋め込みコマンドのサブセットをサポートします: `{embedtitle:...}`、`{embeddescription:...}`、`{embedurl:...}`、`{embedimage:...}`、`{embedthumbnail:...}`、`{embedcolor:57F287}`、 `{embedfooter:...}`、`{embedfooterimage:...}`、`{embedauthor:...}`、`{embedauthorurl:...}`、`{embedauthorimage:...}`、`{embedtime:true}`、`{embedfield:field name:content}`。モデレーション アナウンスでは、AutoReply の反応、条件、遅延、計算、または状態変数は処理されません。

```text
{embedtitle:⛔ 違規處分}
{embeddescription:被處分者：{user}\n原因：{reason}\n結果：{action}}
{embedfield:裁判字號:{case_id}}
{embedfield:執行管理員:{moderator}}
{embedcolor:ED4245}
```

### ケース ID とマルチボットの継続

デフォルトのケース ID 形式は `{roc_year}{sequence:04d}` です。 `{year}`、`{roc_year}`、`{sequence}` (例: `CASE-{year}-{sequence:04d}`) を使用することもできます。形式には `{sequence}` を含める必要があります。

新しいケース ID を生成するとき、ボットはアナウンス チャンネル内の最大 1000 件の履歴メッセージを読み取り、最新のものからプレーン テキストを検索し、タイトル、説明、フィールド、作成者、フッターを埋め込みます。まず現在の case-ID 形式を適用し、次に従来の `裁判字號：1150001` スタイルとの互換性にフォールバックします。複数の競合するケース ID を含むメッセージはスキップされます。検索はこのボットによって送信されたメッセージに限定されないため、同じ形式を使用する他のボットもシーケンスを続行できます。何も見つからない場合、ボットにメッセージ履歴の読み取り権限がない場合、または形式を認識できない場合にのみ、ボットはこのボットによって保存されたサーバー状態に戻ります。

> 異なるボットはロックを共有しません。複数のボットがほぼ同時にアナウンスを生成した場合でも、同じ前の ID を読み取る可能性があります。ボット間で衝突がないことを保証するには、すべてのボットが同じデータベースまたはロック サービスを共有する必要があります。
