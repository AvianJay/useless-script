# 🛡️ AntiBeast — 詐欺防止管理者の自動化について言及

AntiBeast は、Mr. Beast 画像詐欺、大量言及、侵害されたアカウントのボットに対抗するように設計されています。有効にすると、`@everyone`、`@here`、およびバイパス リストに追加されていないロールのメンションをブロックするネイティブの Discord AutoMod ルールが作成されます。

もうミスター・ビースト詐欺はやめましょう 🥀

|コマンド |説明 |
| --- | --- |
| `/antibeast セットアップ` |対話型セットアップ フロー: 概要を表示し、バイパス ロールを構成し、リピート トリガー アクションをセットアップしてから、 | を有効にします。
| `/antibeast 概要` | AntiBeast の機能の説明を見る |
| `/antibeast 切替` | AntiBeast を有効、無効、または切り替える |
| `/antibeast バイパス` |バイパスロールを追加または削除する |
| `/antibeast 設定` |繰り返しトリガー アクションを有効にするかどうか、時間枠、トリガー数、スコープ、および Moderate.py アクションを構成します。
| `/antibeast 一覧` |現在の構成、AutoMod ルール ID、保護されたロール、およびアクション設定を表示します。

## 仕組み

有効にすると、AntiBeast は専用の AutoMod キーワード ルールを同期します。ルールには次のものが含まれます。

- `@everyone`
- `@here`
- バイパス リストに追加されていないすべてのロールのメンション トークン。 `<@&role_id>`

同時に、AntiBeast は `@everyone` ロールの「@everyone、@here、およびすべてのロールのメンション」権限を一時的に有効にするため、詐欺ボットはサーバーが大量のメンションを許可していると信じ込んでしまい、実際のメッセージは AutoMod ルールによってブロックされます。 AntiBeast を無効にすると、`@everyone` ロールの元の権限状態が復元されます。

## ロールをバイパスする

バイパス リストは、Discord AutoMod の除外ロールと同じではありません。 AntiBeast では、ロールをバイパスすることは、「このロールのメンション トークンをキーワード フィルターに入れない」ことを意味します。

バイパス リストの適切な候補は次のとおりです。

- 通常、お知らせで言及する必要がある通知のロール
- 管理者が意図的にメンション可能にしておくイベントのロール
- AntiBeast にブロックされたくない特別なロール

ロールが作成または削除されるたびに、AntiBeast は AutoMod ルールが有効になっているサーバー上で AutoMod ルールを自動的に再同期します。また、ボットが再起動されるたびに 1 回再同期されます。

## トリガーアクションの繰り返し

AntiBeast は、独自の AutoMod ルールのトリガー イベントをリッスンできます。同じユーザーが構成された時間枠内で十分な回数ルールをトリガーすると、構成された Moderate.py アクションが実行されます。

デフォルト設定:

- 時間枠: `10` 秒
- トリガー数: `2`
- アクション: `kick AntiBeast: {time_window} 秒內觸發 {trigger_count} 次`
- 範囲: AntiBeast によって保護されているすべての言及

`action` は Moderate.py のアクション文字列形式を使用します。`kick`、`ban`、`mute` / `timeout` / `to`、を使用できます。 `warn`、`send_mod_message` / `smm`、`force_verify` など。カンマで区切って最大 5 つのアクションを連鎖させることもできます。

「@everyone または @here にメンションしているメンバーのみをプロセスする」が有効になっている場合、バイパスされていないロールのメンション トークンは AutoMod によってブロックされますが、リピート トリガー アクションにはカウントされず、Moderate.py アクションは実行されません。

利用可能な変数:

- `{time_window}`: アクションの実行時に現在構成されている時間枠 (秒単位) に置き換えられます。
- `{trigger_count}`: アクションの実行時に今回到達したトリガー数に置き換えられます。

例:

```text
mute 10m AntiBeast 連續觸發, warn {user} 請勿大量提及
```

```text
ban 0 0 AntiBeast: {time_window} 秒內觸發 {trigger_count} 次, smm
```

## 権限の要件

AntiBeast では、ボットに次のものが必要です。

- サーバーの管理: AutoMod ルールを作成、更新、読み取ります。
- ロールの管理: `@everyone` ロールのメンション許可を調整します。

反復トリガー アクションで `kick`、`ban`、`mute`、またはその他のモデレーション アクションを使用する場合、ボットには、対応するキック メンバー、禁止メンバー、タイムアウト メンバーなどのアクセス許可に加えて、十分に高いロールの位置も必要です。

> **推奨事項:** 最初のセットアップでは、`/antibeast セットアップ` を使用してください。このフローでは、最初に概要を示し、次にバイパス ロールとアクション設定を構成してから、最後に AntiBeast を有効にします。
